# awp-update — changelog

| Date | Version | Engine | Change |
|---|---|---|---|
| 2026-11-19 | 2.3 | awp-generate 2.3 | `verify` runs on the workbook before and after the update: only a check the update broke fails the run. A problem that was already in the workbook (such as a Scope key process without an RCM section) is printed as `ALREADY IN THE WORKBOOK BEFORE THE UPDATE`, listed in the update log, and the workbook is delivered. |
| 2026-11-19 | 2.2 | awp-generate 2.3 | Reads the interview tab of awp-generate 2.3: `show` prints, per control, the expected activity and control and the team's "In place?" and "Gap noted"; findings are written against that expectation, and `check` warns when a finding of no design gap contradicts a control the team marked No or Partly. |
| 2026-11-19 | 2.1 | awp-generate 2.2 | Older workbooks: `apply` moves the walkthrough questions from the foot of each 200 sheet to one tab (`<prefix>200Q`), with the responses, surrounding notes and any column the team added; new `questions` command does only that. The activity rows follow the actual process: each update file lists the process steps of its sheet (`process`, required), `check` prints rows before and after against it and warns on a mismatch, and the list goes to the update log. |
| 2026-11-19 | 2.0 | awp-generate 2.2 | In-place editing replaces sheet rebuilding: only the changed cells are written, rows are inserted or removed singly, and everything else on the 100 and 200 sheets (notes beside the tables, comments, highlighting) stays, so an update no longer stops for staff notes. The walkthrough questions and responses are read-only evidence (change types `question` and `add_question` removed); `show` prints them from the single questions tab of awp-generate 2.2 or from the foot of each 200 sheet in older workbooks, with any other note or comment on the sheet. |
| 2026-11-19 | 1.1 | awp-generate 2.1 | Expected → actual: planning labels ("Expected: …", "Expected process", "(expected)") are tagged by `show`, listed as still open, and refused in new activity, control, background and section-title text; "should" / "is expected to" / "will be" warn; a design conclusion on a row still in planning wording warns. New `section` change to rename a sub-section. Reference: the pattern for writing an activity and a control as fact, with a before/after. |
| 2026-11-19 | 1.0 | awp-generate 2.1 | First release: `show` / `check` / `apply` / `selftest`. Updates the walkthrough sheets (background, activities, controls, design-effectiveness findings, questions and responses) and the RCM (risks, control numbers, design-effectiveness conclusions, audit strategy) from update files written by the model against walkthrough minutes, staff notes and supporting documents; optional changes to test sheets without recorded work. Rebuilds only the changed sheets with the awp-generate builders, protects staff responses, lists anything that cannot be carried over, writes an update log and runs `verify`. |
