# etcmail — ETC adjustment approval email

**Use this skill when** the user sends ETC Projection screenshots — usually with no text at all — or asks for the ETC adjustment / ETC approval email. The screenshots *are* the request: do not ask what to do with them.

**What it produces:** one Outlook draft (`.eml`) the user opens with a double-click and sends. Subject, To, Cc, greeting, the five-column table (Engagement · Change in revenue recognition · Margin after adjustment · Partner In-Charge · Supporting Documents), number formats and colours, the screenshots inside the table and the closing `Best regards,` are all generated by `scripts/etcmail.py`. Your job is to read the screenshots correctly and pass on the user's settings. Never write the email body yourself when the script can run. There is no signature: users add their own in Outlook.

**The user's settings** (default partner, partners' emails, CC) are not in this skill. They are in the agent's instructions as a JSON block headed `etcmail settings`. Copy that block, unchanged, into the input as `"settings"` every time. If the instructions have no such block, build anyway — the script warns that To and Cc are empty — and pass the warning on.

Work inside the folder that contains this `SKILL.md`. Run `python scripts/etcmail.py selftest` once per session (`python3` if `python` is not found). It must print one line starting `SELFTEST PASSED`. Only Python 3 is needed — no packages.

## The screenshots (what to read)

Each engagement comes as **two screenshots**, normally in this order:

1. **Header** — title `ETC Projection | <engagement name>`, a line `Type: … | Client: <CLIENT NAME> | E-<8 digits> | <dates> | <weeks> | Currency: SGD`, and four tiles: Projected Margin, Projected Hours, Projected Cost, Projected Total Engagement Revenue.
2. **Change in Revenue Recognition (Engagement to Date)** — a small box with one amount, e.g. `▼ 499.33 SGD` (red), `▲ 122.04 SGD` (green) or `0.00 SGD` (no arrow). It does not name the engagement.

A single screenshot that shows both the header and the Change in Revenue Recognition box is also fine — it counts as the complete pair.

Pairing: a revenue-recognition box belongs to the header sent **immediately before** it; if the user sent all headers first and then all boxes, pair them in the same order (1st header ↔ 1st box). Several engagements in one message → one email with one row per engagement, in the order sent.

| Field in the input | Read it from | Rule |
|---|---|---|
| `engagement` | header title, the text after `ETC Projection \|` | exactly as shown, keep brackets and years (`School Fund FY25 (RY)`) |
| `code` | header line, `E-` number | 8 digits (`E-12345678`) |
| `client` | header line, after `Client:` | as shown (`MINISTRY OF HEALTH`) |
| `margin` | **Projected Margin** big number (not the "vs Budget" line) | number only: `32.6` |
| `revenue_change` | the Change in Revenue Recognition box | **red ▼ → negative** (`-499.33`), **green ▲ → positive** (`122.04`), no arrow → `0`. Never use Projected Total Engagement Revenue or any "vs Budget" figure |
| `screenshots` | the two image files for that engagement | paths of the uploaded files in your sandbox |
| `partner` | only if the user names a different partner | leave out → `default_partner` in the settings |
| `partner_note` | only if the user says so, e.g. "previously Jane Tan" | written under the partner name: `(Previously Jane Tan)` |
| `client_short` | only if the user gives a short name for the subject | leave out → derived automatically (`MINISTRY OF HEALTH` → `MOH`, `ACME CORPORATION LIMITED` → `Acme`) |

Read every digit and the sign carefully; zoom in on the image if your tools allow. If a value is unreadable or a box is missing for an engagement, that is the only case in which you ask the user — one short question naming the engagement and the missing value.

## Steps

1. `python scripts/etcmail.py selftest` (once per session).
2. **Find the screenshot files.** Run `python scripts/etcmail.py files` (add the upload folder as an argument if your tools name one). It lists every image file the sandbox really has, newest first, with its shape (`header/full view` or `revenue-recognition strip`) and a fingerprint; `= same picture as` marks copies. Count the screenshots you can see in the user's message (M) and the distinct pictures listed (N). Match each screenshot you see to a file by shape and order, and pair them as above. **Every screenshot goes in — never drop one.** If N < M, some screenshots did not reach the sandbox as files (pasted images often all arrive as `image.png` and overwrite each other): still build with the files you have, take the figures from what you see, and tell the user in the reply (step 5).
3. Write `../work/etc_input.json` (outside the skill folder):
   ```json
   {"settings": { …the etcmail settings block from the agent's instructions, unchanged… },
    "engagements": [
     {"engagement": "IA 2025", "code": "E-12345678", "client": "ACME CORPORATION LIMITED",
      "revenue_change": -499.33, "margin": 30.0, "screenshots": ["/mnt/data/img1.png", "/mnt/data/img2.png"]},
     {"engagement": "Governance Review FY25-27", "code": "E-87654321", "client": "MINISTRY OF HEALTH",
      "revenue_change": 122.04, "margin": 26.0, "screenshots": ["/mnt/data/img3.png", "/mnt/data/img4.png"]}
   ]}
   ```
   The order of the two screenshots within an engagement does not matter (the script puts the header first).
4. `python scripts/etcmail.py build ../work/etc_input.json --out ../out` → prints `DRAFT: <path>`, Subject, To, Cc, a table, any `WARN:` lines and `BUILD OK`. On `ERROR:` fix the input and re-run.
5. **Reply** — short, nothing else:
   - the `.eml` file as a download;
   - the Subject / To / Cc lines and the table the script printed (so the user can check the figures against the screenshots);
   - `Screenshots embedded: X of M` (X from `SCREENSHOTS EMBEDDED:`, M from what you saw). If X < M, add one line: *Some screenshots did not reach the file sandbox, so they are missing from the draft. Send them again as attached files (📎) instead of pasting, or take one screenshot per engagement that covers the header down to the Change in Revenue Recognition box.*
   - any other `WARN:` line, in plain words;
   - one line: *Open the file — Outlook opens it as a new draft with the table and screenshots; check and Send.*

Subject rule (done by the script): one engagement → `[For Approval] ETC Adjustment - <engagement name>`; several → `[For Approval] ETC Adjustment - <client short names, comma-separated>` (e.g. `Acme, MOH`).

## If Python cannot run in this chat

Write the email in the reply instead, following exactly the same rules: `Subject:`, `To:` and `Cc:` from the etcmail settings block in the agent's instructions, then the body — `Hi <partner first name>,` / blank line / `Please find the proposed ETC adjustments for your approval:` / the table (five columns as above; revenue change with two decimals, thousands separators, negatives in brackets `(499.33)`; margin with one decimal and `%`; Supporting Documents cell: "paste screenshots") / `Best regards,`. Tell the user to paste the screenshots into the Supporting Documents column. Mention that the draft file could not be produced.

## What not to do
- Do not send email, and do not ask the user to type anything when the screenshots are readable.
- Do not change the format by hand — it lives in `scripts/etcmail.py`. For a one-off different partner, use `partner` in the input; for a permanent change (new partner, new CC) tell the user to edit the etcmail settings block in the agent's instructions (see `ref/agent-builder.md`).
- Do not round or recompute figures: copy what the screenshot shows.
